# Snaply Agent — iOS example

A complete, runnable integration of the Snaply Agent iOS SDK. Clone it, drop in your key, run it.

The whole integration is in [`Sources/SnaplyExampleApp.swift`](Sources/SnaplyExampleApp.swift) —
about fifteen lines of it. Everything else on screen is a fake checkout, there so the SDK has
something realistic to capture.

## Run it

The Xcode project is generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen), so it is never
committed and never goes stale:

```bash
brew install xcodegen
cd Examples/SnaplyExample
xcodegen generate
open SnaplyExample.xcodeproj
```

Before it will connect you need two things:

1. **Your key.** In `SnaplyExampleApp.swift`, replace:

   ```swift
   private let snaplyKey = "snap_live_REPLACE_WITH_YOUR_KEY"
   ```

   Get it from the Snaply console → **Products → your product → API key**.

2. **Your bundle id on the product.** This example uses `com.example.snaplyexample`. Either add
   that to your product's allowed bundle id, or change `PRODUCT_BUNDLE_IDENTIFIER` in `project.yml`
   to one already allowed. Otherwise registration is refused with `origin_mismatch` — which is what
   makes the key safe to ship inside your app.

Then run it. The screen should say *"Connected — this device is now visible in the console."*
Request a screenshot from the console; the consent sheet appears on the device, and nothing is
captured until it is allowed.

## Adding the SDK to your own app

In Xcode: **File → Add Package Dependencies…** and enter

```
https://github.com/Mobile-LLC/SnaplyAgent-SDK-iOS.git
```

or in a `Package.swift`:

```swift
.package(url: "https://github.com/Mobile-LLC/SnaplyAgent-SDK-iOS.git", from: "2.31.0")
```

Then, once at launch:

```swift
Snaply.on(SnaplyCallbacks(onAllowed: { _ in }, onDenied: { }))
Snaply.configure(key: "snap_live_…") { error in /* … */ }
```

`configure` also has an `async throws` form if you prefer it. iOS 15 is the floor.

## Redaction — read this before you ship

**The SDK redacts secure text fields automatically and nothing else.** Everything else on screen is
captured as-is. Mark whatever you want hidden:

```swift
// SwiftUI
TextField("Card number", text: $card).snaplyRedact()
TextField("Address", text: $address).snaplyRedact(label: "HIDDEN")

// UIKit
cardField.snaplyRedact()
cardField.isSnaplyRedacted = true
```

You can also set a view's `accessibilityIdentifier` to contain `snaply-redact`, which is useful
when the view comes from a storyboard.

To restyle every box at once:

```swift
Snaply.setRedactionStyle(SnaplyRedaction(color: .darkGray, label: ""))   // label: "" = plain box
```

The box is painted **on the device, before the image is encoded**, so the underlying pixels never
leave the phone. It is not a blur applied on the server, and there is no version of the frame that
contains the real content.

### The same rule on every platform

iOS, Android and the web all cover password/secure fields and nothing else. What counts as
sensitive is your call — the SDK does not guess, because a guess that is right for one app is
wrong for the next.

## What the SDK does and does not capture

- Captures **your app's own window only** — never other apps, never the home screen. That is why no
  screen-recording permission is requested and no system recording prompt appears.
- Captures **only after the user allows it**. Consent is the product, not a setting.
- While a live session runs, an on-screen indicator stays up, and the SDK stops sending the moment
  it can no longer prove that indicator is attached.

## Identifying your users

```swift
// Known at launch:
Snaply.configure(key: key, user: SnaplyUser(id: "usr_20481", name: "Maya Kowalski"))

// Or later, when they sign in:
Snaply.identify(id: "usr_20481", name: "Maya Kowalski", phone: "+14155550142")

// On sign-out:
Snaply.reset()
```

Without it the device stays anonymous, and support finds it by the support code the person reads
out — `Snaply.showSupportCode()`.

## Errors worth handling

`Snaply.configure` reports failures with a `SnaplyError` carrying a `code`:

| `code` | Meaning |
|---|---|
| `invalid_key` | The key is wrong, or still the placeholder |
| `origin_mismatch` | This app's bundle id is not on the product's allowed list |
| `quota_exceeded` | The workspace is out of screenshots for the cycle |


## Vendor ID

`Snaply.configure(key:..., collectVendorId: false)` opts out of sending the IDFV. It is on by
default, and **you** own the App Store privacy declaration for it: either declare *Identifiers →
Device ID*, or pass `false`. It is never the identity key — an install-scoped UUID is. iOS returns
nil before first unlock after a reboot; treat nil as normal, never as an error to retry.
